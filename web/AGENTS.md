# web

The browser client. The root [AGENTS.md](../AGENTS.md) binds here too, including its loud rule:
**ask the author before deciding anything.** This file holds what the author has decided for the
web client, and what is still open.

**It is loose for now, by the author's choice.** TypeScript in strict mode and Biome are the only
fixed rules. The folders, the file layout and the code style are settled after the first slice works.

**Telegram Web A is the inspiration, for ideas only.** A clone is in `tmp/telegram-tt`. It is
GPL-3.0 and keryx is MIT, so none of its code, styles or assets are copied.

## What has been decided

| Part                      | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Stack                     | React, Vite and TypeScript, with all crypto done by `keryx-core` compiled to WASM                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Layout                    | Three columns, as in Telegram Web A: the chat list, the chat, and a profile panel. Below about 1276 px wide the profile panel overlays, and below about 925 px the list hides behind the chat. A phone, at 600 px and below, shows one screen at a time and slides between them                                                                                                                                                                                                                                                                                  |
| Threads                   | **One Web Worker holds the WASM, the keys, the MLS state, the queue and the WebSocket.** The page sends it commands and gets back decrypted messages to draw. Slow crypto never freezes scrolling, and keys stay out of the page's scripts. The price is a message layer between the page and the worker                                                                                                                                                                                                                                                         |
| Bindings                  | `web/wasm/`, a workspace crate holding only the wasm-bindgen glue around `keryx-core`'s `client.rs`, which holds the flow itself. See the root AGENTS.md and [core/AGENTS.md](../core/AGENTS.md)                                                                                                                                                                                                                                                                                                                                                                 |
| WASM surface              | **One class, chosen by the author:** `Client` with a constructor taking the login kind and the platform, and `step(input, now)` returning the outputs, all `client.rs`'s own enums as plain objects. The worker does the socket, the requests, IndexedDB and the timer. The thinnest glue, and Android does the same                                                                                                                                                                                                                                             |
| TypeScript types          | **Written by `tsify` from core's own types, behind core's `wasm` feature, chosen by the author.** No copies in `web/wasm/` and no hand-written `.d.ts`, so a renamed field breaks the TypeScript build                                                                                                                                                                                                                                                                                                                                                           |
| wasm-bindgen version      | **The crate is pinned to `=0.2.129` in `web/wasm/`, chosen by the author**, to match the CLI installed on the author's machine. Raising it means installing the matching CLI first                                                                                                                                                                                                                                                                                                                                                                               |
| WASM build                | `cargo build --target wasm32-unknown-unknown --release`, then the wasm-bindgen CLI with `--target web`, both in `web/Makefile`. The target checks that the CLI's version matches the `wasm-bindgen` crate in `Cargo.lock`, since they must be identical. No wasm-pack, no Vite plugin                                                                                                                                                                                                                                                                            |
| Page and worker           | Our own typed messages: one TypeScript union of commands the page sends, one of events the worker sends, and one switch on each side, the page's feeding the store. No Comlink. **They are `client.rs`'s own commands and events, chosen by the author**, typed by tsify, which the worker passes through as they are. The worker adds only a few of its own, such as "use here". One list to keep, and Android gets the same one                                                                                                                                |
| Two tabs                  | **One active tab**, through the Web Locks API, since two tabs would each load the device's MLS state and break it. Another tab says keryx is open elsewhere and offers "Use here", which takes over. It works on every browser, including Chrome on Android, which has no SharedWorker                                                                                                                                                                                                                                                                           |
| Developing                | `make dev` runs Vite with hot reload and proxies `/api` to a local `keryx serve`. The dev `server.toml` sets `public_url` to Vite's address, so the Origin check and the cookie match                                                                                                                                                                                                                                                                                                                                                                            |
| Router                    | Our own, about 50 lines: the store holds the path, links push history, and back pops it. No library, and the sliding mobile transitions stay ours                                                                                                                                                                                                                                                                                                                                                                                                                |
| Icons                     | Lucide (ISC), each icon its own React component, so only those used ship                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Device details            | `navigator.userAgentData` where the browser has it, and a small parser of our own for the user agent elsewhere. No library. They are claims anyway                                                                                                                                                                                                                                                                                                                                                                                                               |
| State                     | One Zustand store on the page, with plain functions as actions. Components re-render only for what they read                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Styling                   | CSS Modules in plain CSS, one `.module.css` beside each component. Theme colours are CSS variables. No SCSS, since CSS now has nesting and variables                                                                                                                                                                                                                                                                                                                                                                                                             |
| Building blocks           | Radix primitives for dialogs, menus, popovers and tooltips, which are unstyled and handle focus, keyboard and right-to-left. They are styled with our CSS Modules, and taken one component at a time                                                                                                                                                                                                                                                                                                                                                             |
| Long lists                | `react-virtuoso`, which draws only what is on screen, starts at the bottom, and keeps position when older pages load                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| URLs                      | Paths such as `/c/<chat-id>` through the History API, so the back button closes a chat and reload keeps it. The server already answers any path with no file with `index.html`. A chat id reaches the server's log on reload, which reveals nothing, since the server knows it already                                                                                                                                                                                                                                                                           |
| Theme                     | Light and dark, following the system, with an override in settings                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Languages                 | English and Persian from the start. The whole layout mirrors for Persian, so CSS uses start and end, never left and right. Each message picks its own direction                                                                                                                                                                                                                                                                                                                                                                                                  |
| Translations              | Two typed JSON files, `en` and `fa`, and a small lookup function of our own, with plurals and numbers from the browser's `Intl`. TypeScript catches a missing key. No library                                                                                                                                                                                                                                                                                                                                                                                    |
| Fonts                     | Inter and Vazirmatn, both served by keryx itself, so every device looks the same. About 300 KB. No font comes from Google or any other outside service, since that would tell it who opens the app                                                                                                                                                                                                                                                                                                                                                               |
| Installing                | A PWA that installs to a phone's home screen and opens full-screen. **No service worker caches the code**, so the browser always loads the version the server has, and an old client never runs against a newer server                                                                                                                                                                                                                                                                                                                                           |
| Messages on the device    | **Memory only for now.** Each visit fetches history and decrypts it again, so nothing readable is on disk beyond the keys. The cache is decided together with local search, which needs one                                                                                                                                                                                                                                                                                                                                                                      |
| Loading                   | **The newest message of each chat, then on demand**, chosen by the author since messages are kept in memory only. After the chat list, each chat's newest message is fetched so its preview can be opened. Opening a chat loads its newest page, and scrolling up loads older ones. Fetching all history in the background, as the root AGENTS.md describes for a client with storage, would download and decrypt everything on every visit                                                                                                                      |
| Timeline                  | **The page's store keeps the opened messages.** `client.rs` keeps no timeline and sends each opened message, edit and delete as an event. See [core/AGENTS.md](../core/AGENTS.md)                                                                                                                                                                                                                                                                                                                                                                                |
| Message look              | Bubbles. Your own are on the end side, which is the right in English and the left in Persian, and others' are on the start side. Consecutive messages group together, with the time and the marks inside the bubble                                                                                                                                                                                                                                                                                                                                              |
| Marks                     | As the root AGENTS.md describes under Read state. Waiting while queued and until the sequence id arrives. In a direct chat: one mark, two once delivered, and both change colour once seen. In a group: one mark, which changes colour at the first `seen`. In a channel the waiting sign goes and no mark follows                                                                                                                                                                                                                                               |
| Gestures                  | On touch screens, a swipe from the start edge closes a chat, and swiping a message towards the start begins a reply, once replies exist. Both follow right-to-left                                                                                                                                                                                                                                                                                                                                                                                               |
| First slice               | Sign up, log in, `/setup#token`, the words (generate, confirm and restore), the chat list, directory search to start a chat, and a chat with send, edit and delete and its waiting and sent marks. Also logout, and the device list with terminate, which logout and the device limit need anyway. The profile panel exists but is nearly empty                                                                                                                                                                                                                  |
| Values across WASM        | `serde-wasm-bindgen`, so Rust structs arrive as plain objects and bytes as `Uint8Array`, and `tsify`, which writes the TypeScript types from the Rust ones, so a renamed field breaks the TypeScript build                                                                                                                                                                                                                                                                                                                                                       |
| Browser storage           | Our own small wrapper over IndexedDB: one database, one store, get and put by key. The two snapshot slots follow core's snapshot format. No library                                                                                                                                                                                                                                                                                                                                                                                                              |
| Logo                      | The author approved the redrawn logo in `tmp/logo/`, which is git-ignored, so it moves into the client when `web/` is created. The browser tab's icon is an SVG that turns white when the system is dark, with the PNGs as fallback. Home-screen icons keep their white background. Inside the app the logo takes the theme's text colour. The 16 px icon is the full six-feather mark from `logo.svg`, chosen by the author. The four-feather `logo-16.svg` is not used. `favicon-16.png` and the 16 px image inside `favicon.ico` are rendered from `logo.svg` |
| Colours                   | Black and white like the logo. The accent is `#2F6FEB`, for the marks and the send button in both themes, chosen by the author. White on it, and it on white, are 4.57:1. On the logo's ink `#121212` it is 4.10:1, so it is not used for text there. Links stay the text colour and are underlined                                                                                                                                                                                                                                                              |
| Writing the words down    | After showing them, the client asks for three random positions, each with autocomplete from the English BIP39 list. There is no copy button, since clipboards leak                                                                                                                                                                                                                                                                                                                                                                                               |
| Restoring                 | One box per word, 12 by default and switchable to 24, each with autocomplete. A pasted phrase spreads across the boxes, a wrong word shows at once, and the checksum is checked when the last box is full                                                                                                                                                                                                                                                                                                                                                        |
| Tooling                   | npm and Biome, with everything going through a `web/Makefile`: install, check, build and test                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `make check`              | **Biome and `tsc --noEmit` on the TypeScript, and clippy with `-D warnings` and `cargo fmt --check` on `web/wasm/`, chosen by the author.** `test` waits until there is something to test, since where the espai checks go is still open                                                                                                                                                                                                                                                                                                                         |
| The bare page             | **Vite and TypeScript with no React, chosen by the author:** `index.html` with a few plain fields and buttons and a log of events, `src/main.ts` for the page, `src/worker.ts` for the worker and `src/storage.ts` for IndexedDB. The built glue goes in `src/wasm/`, which is git-ignored. React comes with the first screen, which replaces this page                                                                                                                                                                                                          |
| Files for this slice      | Flat in `web/src/`. One file per screen beside `worker.ts`, and its CSS module beside it. Chosen by the author for now, and looked at again when the first slice works                                                                                                                                                                                                                                                                                                                                                                                           |
| Account screens           | The first screens replace the bare page, chosen by the author: sign up, log in, `/setup#token` and the words. Then stop and show them, before the chat list. `worker.ts`, `storage.ts` and the tab lock stay. Sign up is offered only when `GET /api/v1/public/features` says registration is open. Until that reply, and when it is closed, the screen is log in only. When captcha is on, a row under the password is the same width and height as the fields above it, on every screen. The picture is three quarters of that row and the refresh icon one quarter, and the picture fills its cell. The logo sits higher on these screens so the form, including that row and an error, fits without the page scrolling                                                       |
| Tab lock in the bare page | **Already there, chosen by the author**, since testing in one Chromium makes a second tab likely                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| The dev config            | **`web/dev.toml`, committed, chosen by the author.** `make dev` starts `keryx serve` with it beside Vite. Paths must be absolute, so the Makefile writes a copy with the real paths under the git-ignored `tmp/`                                                                                                                                                                                                                                                                                                                                                 |

## Testing

**The client is tested in the author's own Chromium, driven through the `espai` skill.** Not with
Playwright, Vitest or a browser of its own.
